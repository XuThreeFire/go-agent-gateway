# 架构与数据模型

## 模块关系

```text
Web / CLI → HTTP → service → exec → llm / tool
                       ↓       ↓
                     store ← hub → SSE
                       ↓
                     MySQL
```

HTTP 层负责协议、请求校验、签名会话和资源归属；service 编排创建与提交执行；exec 管理 Agent 循环、并发、取消和终态；llm 适配模型协议；tool 控制工具能力；hub 分配事件序号、保存批次并广播；store 集中实现事务与查询。

读路径可以直接访问 store。只有存在真实变化的接缝才引入接口：模型有模拟与真实适配器，工具有多个实现；执行器和 Hub 的存储接口也便于注入故障测试。

## 核心概念

| 概念 | 含义 | 关键关系 |
| --- | --- | --- |
| Task | 一次会话 | 归属于一个签名会话身份 |
| Turn | 一次用户输入 | 在 Task 内按 seq 排序 |
| Run | 一次执行尝试 | 关联一个 Turn，重试产生新的 attempt_no |
| Step | 一次模型或工具调用 | 记录耗时、用量和工具参数 |
| Event | 一条可回放输出 | 由 run_id、seq 唯一标识 |
| Connection | 一个订阅连接 | 不决定 Run 是否继续执行 |

业务使用六张表：task、turn、run、step、event、usage_counter。初始迁移还保留了暂未启用的 model_config 表；当前模型清单以配置文件为准，不读取该表，避免双重配置来源。

DDL 是 `backend/migrations/` 下的版本化 up/down SQL。使用主键、唯一索引和普通索引，不使用外键及额外 CONSTRAINT；关联一致性由事务和应用规则维护。

## 一致性规则

- 新建 Task、首个 Turn 和首个 Run 在同一事务完成。
- 同一 Task 的追加与重试先锁 Task，再检查是否存在活跃 Run。
- 创建幂等由 `(client_id, idempotency_key)` 唯一索引兜底；幂等重放不重复提交执行。
- 终态通过 `WHERE id=? AND status=?` 更新，只有一个执行路径能成功。
- Step、Run token 汇总、客户端及全局日用量在同一个事务写入。
- Event 批次按 Run 串行提交，提交不确定时可以按唯一索引幂等重试。

实时事件可能先于持久化可见；这是降低输出延迟的取舍。正常终态前刷新正文批次，正常退出等待执行器后再强制刷新尾批。强制断电或 SIGKILL 仍可能丢失未提交的尾批；终态重放不能重建丢失正文。

## 身份与部署范围

签名 Cookie 是本地匿名会话标识，不是完整账号系统。忽略 `X-Client-Id` 与 URL 的 clientId，所有 Task/Run 路径统一检查归属。个人公网用途还要求访问密码与 HTTPS。知道共享访问密码的人可以创建新身份，因此日配额不等同于防滥用计费系统。

仅支持单实例：不要将多个进程指向同一业务库并同时执行启动扫描。扩展到多实例需要执行租约、事件跨进程协调与新的恢复策略。

## 源码中的设计编号

| 编号 | 当前含义 |
| --- | --- |
| D-01 | 执行与订阅连接解耦 |
| D-02 | 重启标记中断，不自动重跑工具 |
| D-03 | 只有未开始输出的 429 才有限重试 |
| D-04 | 进程内信号量限制并发，满时拒绝，不堆积执行 |
| D-05 | 在模型适配器集中处理协议差异 |
| D-06 | 事件批量提交，减少数据库往返次数 |
| D-07 | 浏览器使用原生 EventSource，终态后主动关闭 |

这些编号用于帮助阅读旧源码注释；保障边界以当前实现、测试和可靠性教程为准。

模型运行时支持文件提示词热重载、请求规范化、缓存诊断与本地出站代理，见[专门参考](model-runtime.md)。所有预算仍属于已知 token 用量上的软限制。
